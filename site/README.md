# site/ — заготовка сайта покупки smetana

Статические страницы (без внешних CDN и аналитики — R4/приватность): хостинг — в РФ.

| Файл | Назначение |
|---|---|
| [index.html](index.html) | Стартовая страница: возможности, ссылки на покупку и активацию |
| [buy.html](buy.html) | **Страница покупки:** выбор тарифа, форма (email для чека 54-ФЗ и ключа, согласия EULA/privacy), кнопка «Перейти к оплате» |
| [activation.html](activation.html) | Инструкция офлайн-активации и переноса лицензии |
| [assets/style.css](assets/style.css), [assets/buy.js](assets/buy.js) | Стили; обработчик формы покупки |

## Связь с платежами

`buy.js` отправляет `POST /api/v1/checkout` и ждёт `{ orderId, paymentUrl, … }` —
контракт интеграционного слоя описан в [docs/payments.md](../docs/payments.md) §4.
Пока backend не подключён, форма показывает статус «Онлайн-оплата пока не подключена» —
это ожидаемое поведение заготовки.

Порядок подключения к продажам:

1. Поднять backend «Заказы и лицензии» (контракт docs/payments.md §4) на хостинге в РФ.
2. В личном кабинете агрегатора (ЮKassa / CloudPayments) получить ключи sandbox → прогнать e2e (payments.md §5).
3. Заменить цены `TBD ₽` в [buy.html](buy.html) на утверждённые (спека §7).
4. Выставить `PUBLIC_BASE_URL`, перевести форму на боевые ключи, проверить чеки 54-ФЗ.

## Замечания

- Ссылки на юридические документы ведут в `../docs/legal/` — при публикации сайта
  скопируйте эти файлы в `site/legal/` или настройте маршруты веб-сервера.
- Локализация: v1 — русская версия (основной рынок); EN-версия страниц — в планах
  вместе с локализацией продукта (задача 6.3).
- Иконка/логотип: подставить `assets/logo.png` перед релизом (см. docs/release.md §11).
