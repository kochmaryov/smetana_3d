# SmetaNA — план: палитра инструментов и настройка интерфейса

- **Статус:** черновик плана (спека утверждена 2026-10-24, макет — вариант A)
- **Основание:** [спека tool-palette.spec.md](../specs/tool-palette.spec.md) (T1–T8, DoD §5), макет [variant_a_palette.html](../../data/temp/tool_ui_variants/variant_a_palette.html)
- **Исполнение:** координатор + делегированные чаты в изолированных worktree (правила — §4); оценки — в человеко-днях (чел/дн)
- **Связь с планом v1.0:** закрывает задачу 6.1 [3d-editor.plan.md](./3d-editor.plan.md) («лента инструментов» → палитра иконок); палитра команд Ctrl+K — отдельная спека (M10 v1.x)

## 0. Рамки и стратегия

**Рамки:** меняется только панель инструментов и её настройка; VCB, вьюпорт, правая панель, меню — не трогаем. Стек — Avalonia 12, существующие `ToolDefinition` / `Register*Tools` / `ShortcutMap` / `ToolController` не переписываются. Строки — модульные классы в стиле `DrawingToolStrings` (общий `Strings.resx` не трогаем — конвенция проекта).

**Стратегия:**

1. **Контракт до параллелизма.** Волна 0 (координатор) замораживает `ToolGroupRegistry`, модель раскладки и контракт иконки — дальше три чата работают против фиксированных интерфейсов.
2. **Вертикальный срез.** Уже в волне 0 палитра-каркас (группы, две колонки, текстовые заглушки кнопок) врезается в `MainWindow` — параллельные треки сразу видят свой код в приложении.
3. **Тесты на каждый трек.** Юнит-тесты в `tests/SmetaNA.EditorUI.Tests`; каждый чат заканчивает задачу зелёным прогоном своего фильтра.
4. **Интеграция одной рукой.** `MainWindow.axaml(.cs)`, `SmetaNA.EditorUI.csproj`, общие строки — только координатор (правило §4.2 основного плана).

**Сводка:**

| Волна | Содержание | Оценка | Календарь |
|---|---|---|---|
| 0. Контракты и каркас (координатор) | реестр групп, модель раскладки, контракт иконки, каркас палитры в MainWindow | 3–4 чел/дн | ~1 нед, сериально |
| 1. Параллельные треки | A: иконки ∥ B: палитра ∥ C: раскладка + диалог | 3–4 ∥ 5–7 ∥ 6–8 чел/дн | ~1–1.5 нед, параллельно |
| 2. Интеграция (координатор) | врезка, свап иконок, смоук, полный сьют, чек-лист адаптивности | 4–5 чел/дн | ~1 нед, сериально |

**Итого: 21–28 чел/дн (~4–5.5 чел/нед); календарно ≈ 2.5–3 недели при трёх параллельных чатах.** Критический путь — волны 0 и 2 (координатор); треки не сжимают его, только середину.

## 2. Волна 1 — параллельные треки

### Чат A — набор иконок · 3–4 чел/дн

- **Вход:** контракт 0.3 (`ToolIconId`), макет variant_a (стиль глифов).
- **Владение файлами:** `src/SmetaNA.EditorUI/Icons/**`, свои тесты в `SmetaNA.EditorUI.Tests` (класс `ToolIconTests`).
- **Задачи:** A1 — 24 глифа 24×24 (stroke, `currentColor`) как ресурсы Avalonia; A2 — маппинг всех 24 commandId → `ToolIconId` (включая под-инструменты вылетов); A3 — отрисовка в обеих темах (проверка контраста), размеры 38/44 px; A4 — тултип-формат «Имя · жест» (данные уже есть в `ToolStubViewModel`).
- **Валидация:** юнит-тест «у каждого commandId есть глиф»; визуальная сверка с макетом (своей части).
- **DoD спеки:** 1 (иконки), 4 (жесты в тултипах), 5 (темы).

### Чат B — палитра UI · 5–7 чел/дн

- **Вход:** контракты 0.1/0.3/0.4, каркас 0.5, макет variant_a (окно).
- **Владение файлами:** `src/SmetaNA.EditorUI/ToolPalette/**` (кроме реестра/строк из волны 0 — их правит координатор), свои тесты (`ToolPaletteViewModelTests`).
- **Задачи:** B1 — `ToolPaletteViewModel`: группы, кнопки, активный инструмент (`ToolController`), подсветка шага урока (`IsHighlighted`); B2 — вылет-меню для Дуги и Зеркала (все 5 под-инструментов, T4); B3 — тултипы «Имя · жест» + пояснение `HintKey` в режиме «Новичок» (T7); B4 — адаптив: 2 колонки → 1 колонка (≤ 960 px) → рейл с вылетами (≤ 768 px) + свёртка групп при переполнении (риски R1/R2).
- **Валидация:** юнит-тесты VM (состав групп, выбор инструмента, вылеты); визуальная сверка на 1280×800 и 768 px с макетом.
- **DoD спеки:** 1, 2, 7; частично 6 (свои размеры экрана).

### Чат C — раскладка и диалог настройки · 6–8 чел/дн

- **Вход:** контракты 0.2/0.4, макет variant_a (диалог «Настройка панели инструментов»).
- **Владение файлами:** `src/SmetaNA.EditorUI/ToolLayout/**`, свои тесты (`ToolLayoutModelTests`, `ToolLayoutStoreTests`, `ToolLayoutDialogViewModelTests`).
- **Задачи:** C1 — `ToolLayoutStore`: JSON в каталоге настроек приложения, версия схемы, миграция (risk R4), дефолты из `ToolGroupRegistry`; C2 — применение раскладки к реестру без перезапуска; C3 — диалог: дерево «Все инструменты» ↔ «Панель», drag&drop порядка, свои группы (создать/переименовать/удалить; системные — только скрыть), свойства кнопки, «Сбросить»; C4 — кастомные группы переживают перезапуск (T8).
- **Валидация:** юнит-тесты: round-trip сохранения, миграция vN→vN+1, сброс к умолчанию; ручной сценарий «скрыть 3 инструмента → перезапуск».
- **DoD спеки:** 3 (настройка), 8 (перезапуск); частично 6 (диалог на 768 px).

**Синхронизация треков:** свап «заглушка → иконки» (A ↔ B) — только через контракт 0.3, без правок файлов друг друга; стыковка «палитра ↔ раскладка» (B ↔ C) — через `IToolLayoutStore`/`ToolLayoutModel`. Мелкие merge после каждой задачи.

## 4. Правила делегирования (параллельные чаты)

1. Каждый чат — отдельная сессия в изолированном worktree; ветка `feature/tool-palette-<track>`.
2. **Владение файлами:** чат A — `Icons/**`, чат B — `ToolPalette/**`, чат C — `ToolLayout/**`; `MainWindow.*`, `SmetaNA.EditorUI.csproj`, `ToolGroupRegistry`, `ToolLayoutModel`, строковые классы — только координатор.
3. Контракты волны 0 заморожены; расхождение — доклад координатору, не «костыль» в треке.
4. Единый контур качества: каждый чат завершает задачу `dotnet build` + `dotnet test tests\SmetaNA.EditorUI.Tests\SmetaNA.EditorUI.Tests.csproj` (свой фильтр); координатор — полным сьютом после каждого merge.
5. Merge — мелкими порциями после каждой задачи; сверка треков на границе волн (1 раз в неделю).
6. **Интеграционный чек-лист координатора:** `dotnet build SmetaNA.slnx` → `dotnet test` (все проекты) → `--smoke` → чек-лист адаптивности → сверка с макетом → обновить спеку.

**Брифы для запуска чатов** (копируются в делегированный чат как есть):

- **Чат A:** «Реализуй набор иконок палитры инструментов по спеке `docs/specs/tool-palette.spec.md` (T1/T6) и макету `data/temp/tool_ui_variants/variant_a_palette.html`. Владеешь `src/SmetaNA.EditorUI/Icons/**`. Контракт `ToolIconId` не менять. 24 глифа 24×24 stroke, `currentColor`, маппинг всех commandId. Тесты — `ToolIconTests`. Финиш: `dotnet build` + `dotnet test --filter ToolIcon` зелёные.»
- **Чат B:** «Реализуй палитру инструментов (VM + view) по спеке `docs/specs/tool-palette.spec.md` (T1/T2/T4/T7) и макету `data/temp/tool_ui_variants/variant_a_palette.html`. Владеешь `src/SmetaNA.EditorUI/ToolPalette/**` (кроме реестра и строк — они заморожены). Иконки — через контракт `ToolIconId` (сейчас заглушка). Адаптив 2 колонки / 1 колонка / рейл. Тесты — `ToolPaletteViewModelTests`. Финиш: `dotnet build` + `dotnet test --filter ToolPalette` зелёные.»
- **Чат C:** «Реализуй хранение раскладки и диалог настройки панели по спеке `docs/specs/tool-palette.spec.md` (T3/T8) и макету `data/temp/tool_ui_variants/variant_a_palette.html` (модалка). Владеешь `src/SmetaNA.EditorUI/ToolLayout/**`. Контракты `ToolLayoutModel`/`IToolLayoutStore` не менять. JSON с версией схемы и миграцией, свои группы, drag&drop, сброс. Тесты — `ToolLayout*Tests`. Финиш: `dotnet build` + `dotnet test --filter ToolLayout` зелёные.»

## 6. Риски плана

| Риск плана | Реакция |
|---|---|
| Конфликт общих файлов (MainWindow, csproj, строки) при параллелизме | Жёсткое владение файлами §4.2; общее — только координатор |
