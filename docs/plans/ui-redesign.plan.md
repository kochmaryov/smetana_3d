## 0. Рамки и стратегия

**Рамки:** меняется только UI-слой `SmetaNA.EditorUI` (AXAML + VM представлений + настройки вида). Не трогаем: рендеринг (`SmetaNA.Rendering`), ядро, инструменты (`ToolController`, `Register*Tools`), форматы, `ShortcutMap`-логику жестов. VM-контракты `MainWindowViewModel` сохраняются (привязки переносятся, не переписываются).

**Ключевое открытие аудита:** кисти `ThemeBorderMidBrush`, `ThemeControlBackground`, `ThemeBackgroundBrush`, `ThemeAccentBrush` используются во всех панелях, но **нигде не определены** (`DynamicResource` резолвится в пустоту) — отсюда «плоский дешёвый» вид. Волна 0 это чинит и задаёт токены темы — фундамент всех остальных волн.

**Стратегия:**

1. **Сначала токены** (волна 0): единый словарь ресурсов (dark — базовый, light — производная) до правки экранов — иначе каждая волна смешивает вёрстку и цвета.
2. **Вертикальные срезы волн:** каждая волна заканчивается собирающимся приложением и зелёным полным сьютом.
3. **Строки — только через локализацию:** новые ключи в `Strings.resx`/`Strings.en.resx` + `LocalizedStrings`; модульные классы — для строк модулей (конвенция `ToolPaletteStrings`).
4. **Настройки вида — версионированный JSON:** раскладка плавающих групп — рядом с `tool-layout.json`, паттерн схемы/миграции переиспользуется.
5. **Тесты на новые VM:** `FloatingGroups*`, `CommandPalette*` — юнит-тесты в существующем стиле.

**Сводка:**

| Волна | Содержание | Оценка | Результат |
|---|---|---|---|
| 0. Токены и тема | словарь токенов (dark/light), определение `Theme*Brush`, базовые стили | 1–2 чел/дн | глубина и цвет во всём приложении |
| 1. Каркас главного окна | одна шапка, статус-строка VCB, виджеты вьюпорта | 2–3 чел/дн | жалобы №1/№3 на главном экране |
| 2. Док с вкладками | Popup → TabControl док; стилизация 5 панелей | 2–3 чел/дн | панели не перекрывают сцену |
| 3. Перемещаемые группы | tear-off, плавание, зоны краёв, JSON v2 | 3–4 чел/дн | требование заказчика |
