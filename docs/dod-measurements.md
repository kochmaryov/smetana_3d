# DoD-замеры (автоматизируемые)

Замеры критериев готовности из [3d-editor.spec.md §5](./specs/3d-editor.spec.md)
для задач 4.5–4.6 фазы 4. Все числа получены **на машине разработчика**
(Windows 11 x64, Intel Core Ultra / Intel Arc 140V, .NET 10.0.402, Debug) —
**машина не эталонная**: эталон DoD §5.6 — 8 ГБ RAM / Intel UHD 620 (2018) без
дискретной видеокарты. Числа на эталонной конфигурации не подтверждались.

Зона печати и её архитектура — в [print-volume.md](./print-volume.md).

## 1. Сценарий S1 «стакан» (DoD §5.2) — бенчмарк последовательности инструментов

Тест: `tests/SmetaNA.Core.Tests/S1CupScenarioBenchmarkTests.cs`
(`S1_CupToolSequence_RunsWithinBudget`). Последовательность повторяет сценарий
S1 «Первое знакомство»: заготовка 60×60×80 мм (API меша) → инструменты:

| Шаг | Инструмент и действие | Время, мс |
|---|---|---|
| 1 | Push/Pull: вдавливание полости −75 мм (дно 5 мм) | 23,1 |
| 2 | Push/Pull: подгонка дна +2 мм (дно 7 мм) | 0,16 |
| 3 | Окружность R20 мм: разметка дна | 35,1 |
| | **Итого последовательность** | **63,2** |

* Первый шаг включает прогрев JIT; устойчивое время шага Push/Pull — < 1 мс
  (см. §2). Бюджет теста — 2000 мс (страховка от регрессий, не норматив).
* После шагов 1–2 меш остаётся замкнутым (watertight), история — 3 команды,
  undo возвращает заготовку — всё проверяется в тесте.
* Сам критерий §5.2 («новичок за ≤ 15 минут») — юзабилити-замер (задача 6.6 плана);
  здесь замерена машинная стоимость последовательности инструментов.

**Наблюдение (расхождение ядра):** рисование по грани
(`AddDrawingShapeCommand`) добавляет контур и грань поверх существующей, не
разрезая её (как в SketchUp), а Push/Pull перемещает грань со склеиванием
вершин — «настоящая» полость с вертикальными стенками через инструменты пока
недостижима (шаг 1 даёт полость с наклонными стенками). Поэтому эталонные
модели для печати строятся API меша (§4), а шаги инструментами используются
для замера отклика. Задел — волна Core (разрезание граней/экструзия).

## 2. Отклик push/pull ≤ 16 мс (DoD §5.6)

Тест: `tests/SmetaNA.Core.Tests/PushPullLatencyBenchmarkTests.cs`
(цикл: план переноса `MeshEditOps.PlanFaceMoveAlongNormal` + `Apply` + `Revert`
— путь коммита операции; 5 прогревов + 30 замеров, отчёт по медиане/percentile).

| Сцена | Медиана | min | p95 | max | DoD ≤ 16 мс |
|---|---|---|---|---|---|
| Меш ~50k треугольников (~25k вершин) | **4,7 мс** | 3,7 | 5,3 | 5,6 | ✅ выполняется |
| Демо-сцена 500k треугольников (~251k вершин) | **38–76 мс** (по прогонам) | 36 | до 96 | до 107 | ❌ не выполняется |
| Наведение (пик грани под курсором), 500k | 136 мс | 126 | 168 | 191 | см. ниже |

Выводы:

* **Цель DoD ≤ 16 мс выполняется для моделей порядка десятков тысяч
  треугольников** (типовой размер модели школьного проекта/корпуса).
* На демо-сцене 500k коммит push/pull превышает цель в 2–5 раз: перенос со
  склеиванием проходит по **всем** вершинам меша (`MeshEditOps.PlanMove`,
  glue-scope = весь меш), стоимость O(N) на каждый коммит. Митигация (задел,
  файлы Core вне текущих границ владения): хеш/пространственный индекс
  позиций для glue-scope.
* Наведение (пик лучом по всем граням `SceneFacePicker`) на 500k — ~136 мс;
  в UI наведение троттлится до 25 Гц, но крупные сцены ощутимо деградируют.
  Митигация — BVH/пространственный индекс для пиккинга (задел Core).
* Тесты фиксируют текущий уровень регрессионными бюджетами (16 мс на 50k,
  250 мс на 500k) — целевые числа DoD вынесены в этот отчёт.

## 5. Чек-лист ручного прогона в PrusaSlicer и Cura (задача 4.6)

Сами слайсеры запускаются вручную (автоматизация не входит в задачу). Для
каждого из 9 файлов из §4 выполнить:

### PrusaSlicer (2.7+)

1. File → Import → Import STL/3MF…, выбрать файл (начать с `cup.3mf`).
2. Модель появляется на столе **автоматически** (auto-arrange) — проверить, что
   она лежит на столе, не «провалилась» и не висит.
3. Выбрать профиль принтера: Original Prusa i3 MK3S (0.4 nozzle), слой 0.2 мм.
4. Нажать «Slice now» — убедиться: **нет ошибок** (non-manifold, holes,
   «model contains errors»), нет предупреждений о единицах.
5. В превью слоёв пройти ползунок от 0 до верха: без пропусков/артефактов
   (особенно: дно стакана, стык ступеньки подставки, вырез корпуса).
6. Проверить габариты в карточке объекта (Size): совпадают с таблицей §4
   (допуск 0,01 мм) — стакан 60×60×80, подставка 100×60×50, корпус 100×80×40.
7. Зафиксировать: время печати/филамент (ориентир для документации).
8. Повторить для `*.bin.stl` и `*.obj` тех же моделей (единицы — мм, масштаб 1:1).

### Ultimaker Cura (5.x)

1. File → Open File(s)…, выбрать файл; модель на столе, авто-размещение.
2. Printer: Creality Ender-3 (или Generic Marlin), сопло 0.4 мм, слой 0.2 мм.
3. Prepare → Slice: **без ошибок** и предупреждений о «mesh not watertight» /
   «model is not manifold» (использовать «Mesh Tools» / «Check models»).
4. Просмотр слоёв (Layer View): пропусков нет, вырез корпуса чистый.
5. Габариты в панели объекта — сверка с §4 (0,01 мм).
6. Повторить для STL/OBJ/3MF каждой модели.

### Критерии приёмки 4.6

* Все 9 файлов открываются в обоих слайсерах без ошибок.
* Слайсинг завершается без жалоб на manifold/watertight (валидатор §5.9 —
  `PrintabilityValidator` — уже подтверждает замкнутость).
* Габариты после импорта совпадают с эталонными (± 0,01 мм, DoD §5.4).
* Превью слоёв без артефактов; вырез корпуса проходит печать без поддержек
  (корпус печатается открытым верхом вверх).

Таблицу результатов заполнить по итогам прогона (статус по каждой модели):

## 6. FPS вьюпорта на демо-сцене 500k (DoD §5.6)

Демо-сцена: `DemoSceneFactory` — 16 чанков рельефа, ровно **500 000
треугольников** (504 000 рёбер). С 2026-10-27 (задача 6.0) рельеф не сеется
при старте — стартует лёгкая эталонная сцена; для замеров сцену 500k нужно
включить флагом **`--demo-terrain`**.
Замер — GUI-прогон с отключённым лимитом кадров (12 с, свой frame pacing
выключен): `SmetaNA.EditorUI.exe --smoke 12 --fps 0 --demo-terrain [--wgl]`, строка `[VIEWPORT]`.

| Режим GL | Средний FPS | Мин. FPS | мс/кадр | Примечание |
|---|---|---|---|---|
| ANGLE (D3D11), дефолт | **140,1** | 135,1 | 6,87 | Intel Arc 140V |
| WGL (OpenGL 4.0) | **78,3** | 73,5 | 11,70 | тот же GPU |
| ANGLE + включённая зона печати | 76,6 | 73,5 | 13,73 | худший случай: вся сцена вне зоны, подсвечены все 500k треугольников |

* Цель DoD ≥ 30 FPS **выполняется на этой машине** во всех режимах; на
  эталонной минимальной конфигурации (Intel UHD 620) результат **не
  подтверждён** — требуется прогон 6.7/DoD на эталонном железе.
* Подсветка «за пределами зоны» на сцене, где вне зоны все 500k треугольников
  (нехарактерный случай для печати), стоит ~7 мс/кадр; для реальных моделей
  печати (единицы тысяч треугольников) накладные расходы пренебрежимы.
* CPU-путь подготовки кадра (бенчмарк `ViewportBatchBenchmarkTests`):
  `SceneRenderModel.Build` 240 мс + `SceneBatcher.Build` 13 мс (перестройка
  после правок сцены), построение оверлея зоны печати 52 мс (только при смене
  профиля/сцены при включённой зоне).

## 7. Как повторить замеры

```
dotnet test tests/SmetaNA.Core.Tests --filter "FullyQualifiedName~S1CupScenario"
dotnet test tests/SmetaNA.Core.Tests --filter "FullyQualifiedName~PushPullLatency"
dotnet test tests/SmetaNA.Rendering.Tests --filter "FullyQualifiedName~ViewportBatchBenchmark"
src/SmetaNA.EditorUI/bin/Debug/net10.0/SmetaNA.EditorUI.exe --smoke 12 --fps 0 --demo-terrain
src/SmetaNA.EditorUI/bin/Debug/net10.0/SmetaNA.EditorUI.exe --smoke 12 --fps 0 --demo-terrain --wgl
```

(Путь к dotnet: `C:\Users\mnk\.dotnet\dotnet.exe`; имена тестов печатают
строки `[S1]`/`[BENCH]` — смотреть логгером `console;verbosity=detailed`.)

## 8. Прочие наблюдения

* Смоук-прогон окна (`--smoke`) на 2026-10-27 проходит полностью
  (`result=PASS`, включая `historyWired`/`undoRedoWired`): VCB-значение на
  свежем инструменте «Линия» не потребляется инструментом (`LineTool.TryApplyValue`
  требует начатой ломаной) и фиксируется в истории командой-заглушкой
  (`StubEditCommand`) — поэтому проверка записи истории срабатывает. Прежние
  наблюдения (2026-10-23: `result=FAIL` по `historyWired`) устарели.
