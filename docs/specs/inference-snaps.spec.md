## 1. Цель

Сделать привязки в редакторе **видимыми, предсказуемыми и полными**: пользователь должен иметь возможность поставить точку ровно в координату или ровно в часть объекта (вершину, ребро, грань, центр, пересечение), зафиксировать направление и при необходимости ввести координаты числом.

Сейчас inference-движок уже считает точечные и линейные привязки, но:

1. **их не видно** — UI не рисует ни маркеров, ни подписей, ни направляющих линий;
2. **они неполные** — нет привязки «на ребро», продолжения ребра («от точки»), осей и начала координат групп/компонентов, сетки;
3. **они не покрывают инструменты** — Move/Rotate/Scale/Offset вообще не используют inference, а координатный ввод VCB для Move — заглушка ([MainWindowViewModel.cs:531](../../src/SmetaNA.EditorUI/ViewModels/MainWindowViewModel.cs));
4. **их нельзя зафиксировать** — `SnapModifiers` есть в модели, но клавиатура (Shift, стрелки) до движка не доходит: `ToolKey` знает только Escape/Enter/Delete ([ToolInput.cs](../../src/SmetaNA.Core/Tools/ToolInput.cs));
5. **у точки нет идентичности** — снимок сцены хранит только мировые координаты, поэтому нельзя подсветить ребро/грань, к которым привязались, и показать, что привязка идёт к геометрии внутри группы или компонента.

**Критерии успеха:**

1. Курсор в пределах 8 px от вершины/середины/пересечения **всегда** даёт точку с точностью ≤ 0,001 мм; тип привязки показан подписью и маркером.
2. Все инструменты, которые запрашивают точку (рисование, размеры, Move/Rotate/Scale/Offset), используют один и тот же inference-контракт; «Рулетка» подключается к нему, когда появится.
3. Координату можно задать числом (абсолютно и относительно) для любой точки построения; результат совпадает с введённым значением с точностью ≤ 0,01 мм.
4. Сетка с настраиваемым шагом включается/выключается и не мешает точным привязкам к геометрии.
5. В сцене 200 000 рёбер обработка движения указателя — ≤ 8 мс (P95), без просадки ниже 30 FPS.

## 2. Область действия

### Входит

- **Привязки к частям объектов:** вершина (endpoint), середина ребра и дуги, точка на ребре, точка на грани, центр окружности/дуги/полигона/грани, пересечение рёбер, направляющих и рёбер с гранями, перпендикуляр (в т. ч. к грани), параллель, касательная, продолжение ребра и выравнивание от точки.
- **Привязки к координатам:** начало координат мира, оси X/Y/Z (красная/зелёная/синяя), начало координат и оси активного контекста (группы/компонента), сетка с шагом, координатные подсказки (X/Y/Z курсора и смещение от опорной точки), числовой ввод координат (абсолютных и относительных).
- **Блокировки:** Shift — фиксация активного направления/плоскости; стрелки — фиксация осей (→ X, ← Y, ↑ Z) и параллели/перпендикуляра (↓); Alt — переключение режимов линейных привязок; Shift+Alt — фиксация плоскости по наведённой грани.
- **Визуальные подсказки:** маркеры типов, подписи, подсветка ребра/грани/контура, пунктирные линии продолжений, линии осей, индикатор блокировки, координатная строка.
- **Настройки** (толеранс, шаг сетки, включение категорий, показ подписей) с сохранением в каталог настроек приложения.
- **Идентичность сущностей** в снимке сцены: стабильная ссылка на узел сцены и элемент меша для подсветки и диагностики.

### Не входит (non-goals этой итерации)

- **Пользовательские точки сборки (Snaps)** в духе SketchUp 2023.1+ (диск с точкой, Alignment Direction и up на части компонента, прилипание snap-to-snap «передняя к передней», режим Stamp, «tractor beam») — проектируется в модели данных, реализуется в v1.x (см. §6.1 R-11, §11 W5).
- Привязки к секущим плоскостям и «разрезам», к теням/фото-подложкам, геолокации.
- Привязки в 2D-документации (Layout-подобный режим) и в экспорте.
- Автоматическое «магнитное» соединение целых компонентов (сборка «как в LEGO»).
- Полноценная система ограничений (constraint solver) — inference остаётся эвристикой наведения, а не параметрикой.
- История/дерево построений (см. non-goals основной спеки).

### Решения по объёму (утверждено 2026-11-05)

| Вопрос | Решение |
|---|---|
| Объём итерации | Волны **W1–W4** целиком: `OnEdge` и продолжения, сетка и `Length Snapping`, координатный ввод во всех инструментах, визуальные подсказки, блокировки, Move/Rotate/Scale/Offset на inference, оси и origin контейнеров. Пользовательские Snaps — **v1.x** (W5) |
| Shift и стрелки | **Гибрид:** стрелки — переключатели (нажал/снял), Shift — фиксация **на время удержания** |
| Координаты внутри контекста | **Переключатель в статус-строке**, по умолчанию **локальные** координаты активного контекста; вне контекста — мировые |
| Сетка и точность | **Обе независимо:** сетка по шагу (выключена по умолчанию) + `Length Snapping` по точности отображения (тоже выключен) |
| Середина ребра vs «На ребре» | Без фиксации — **середина**; при зафиксированном ребре — **«На ребре»** |
| Скрытая геометрия | **И режим отображения, и модификатор:** `Ctrl+Shift` (удержание) временно включает скрытую геометрию; постоянный режим — команда вида |
| Пользовательские Snaps (v1.x) | **Полная сборка:** точка + orientation (`direction`/`up`), snap-to-snap «передняя к передней», Stamp mode, tractor beam |

## 3. Как это устроено в SketchUp

Источники — Help Center (актуальные адреса проверены 2026-11-05; старые слаги `/inference-types`, `/inference-locking` отдают 404), release notes и Ruby API. Ниже явно помечено, что подтверждено документацией, а что — только форумом/наблюдением. Полный список ссылок — в §14.

### 3.1. Таксономия inference

Документированная формулировка ([introducing-drawing-basics-and-concepts](https://help.sketchup.com/en/sketchup/introducing-drawing-basics-and-concepts)):

> «SketchUp displays several types of inferences: **point, linear, and shape**. SketchUp often combines inferences together to form a **complex inference**. Components and dynamic components have their own inference types.»

То есть три класса (точка, линия, форма) плюс их комбинации; для компонентов обещан отдельный набор типов, но он **не перечислен** — это документированный пробел.

**Точечные типы (13, документированы):**

| Тип | Документированное значение |
|---|---|
| Origin point | точка пересечения трёх осей |
| Component Origin Point | начало осей внутри группы/компонента и «точка вставки по умолчанию» |
| Endpoint | конец линии, дуги или сегмента дуги |
| Midpoint | середина линии, ребра или сегмента дуги |
| Arc Midpoint | середина дуги (отдельный тип) |
| Intersection | точка, где линия пересекает **другую линию или грань** |
| On Face | точка, лежащая на грани |
| On Edge | точка, лежащая на ребре |
| Center | центр круга, дуги или полигона |
| Guide Point | точка направляющей |
| On Line | точка вдоль направляющей линии |
| On Section | точка, где инструмент создаёт ребро на секущей плоскости |
| Intersection with Hidden Section | точка пересечения ребра скрытого разреза с инструментом |

**Линейные типы (9, документированы):**

| Тип | Документированное значение |
|---|---|
| On Red Axis | выравнивание по красной оси |
| On Green Axis | по зелёной оси |
| On Blue Axis | по синей оси |
| From Point | выравнивание **от точки**; цвет пунктирной линии соответствует направлению оси |
| Through Point | рисование из одной точки с наведением на вторую и **Shift** — фиксируется направление из начала построения через вторую точку |
| Parallel | параллельно ребру |
| Extend Edge | продолжение существующего ребра |
| Perpendicular | перпендикулярно ребру |
| Perpendicular to Face | перпендикулярно грани |
| Tangent at Vertex | дуга, касательная к вершине ранее нарисованной дуги |

**Формы (shape inference):** документированы для прямоугольника — «квадрат» и «золотое сечение»: при достижении пропорции появляются **синие точки** и ScreenTip, Shift фиксирует это состояние ([drawing-basic-shapes](https://help.sketchup.com/en/sketchup/drawing-basic-shapes)).

**Complex inference** назван, но не определён. Для нас это основание определить комбинированную привязку явно (§7.3): точка + линейное ограничение, с отдельным маркером и приоритетом.

### 3.2. Поведение точечных привязок

- Документированный механизм приоритета — **«пауза над точкой»**: «By pausing your cursor over a location you want to infer from, SketchUp will prioritize aligning with that point when drawing» (там же). Численного толеранса и формального порядка «endpoint vs midpoint vs on-edge» в документации **нет**.
- Ruby API раскрывает семантику ограничений через `InputPoint#degrees_of_freedom` ([ruby.sketchup.com/Sketchup/InputPoint.html](https://ruby.sketchup.com/Sketchup/InputPoint.html)): **0** — конец ребра или пересечение; **1** — на ребре или на оси; **2** — на грани; **3** — свободное пространство. Это удобная модель для нас: кандидат несёт степень свободы, и инструмент понимает, можно ли продолжать построение вдоль ребра/оси/грани.
- Точка вставки компонента документирована как «Component Origin Point»; отдельных типов «On Component»/«Hidden»/«Axes» нет.
- Секущие плоскости (`On Section`, `Intersection with Hidden Section`) — вне нашей текущей итерации (секущих плоскостей ещё нет).

### 3.3. Линейные привязки и продолжения

- Линейная привязка «прилипает вдоль линии или направления»; при рисовании иногда показывается **временная пунктирная линия** (документировано).
- **От какой точки строится ограничение:** документировано только для `Through Point`: анкер — начало текущей операции, вторая наведённая точка даёт направление, Shift фиксирует это направление. Для `From Point`/`Extend Edge` время жизни пунктира и правило выбора анкера при нескольких наведённых точках **не документированы** (пробел; в нашей спеке поведение задаётся явно, §8.2).
- `From Point` — пунктирная линия **от точки**, цвет соответствует направлению оси; `Extend Edge` — продолжение существующего ребра. Это два разных типа, и мы реализуем их раздельно.
- `Parallel`/`Perpendicular` в интерфейсе окрашиваются в **magenta** (документировано в таблице блокировок: «anything that turns magenta»).
- `Perpendicular to Face` и `Tangent at Vertex` — документированы; у нас появятся как расширение (P1/P2).

### 3.4. Блокировка привязок

Документированная таблица ([introducing-drawing-basics-and-concepts](https://help.sketchup.com/en/sketchup/introducing-drawing-basics-and-concepts), раздел «Locking inferences with a keyboard»):

| Клавиша | Документированное поведение |
|---|---|
| ↑ | фиксирует направление/плоскость построения по **синей** оси |
| ← | по **зелёной** оси |
| → | по **красной** оси («Right locks Red») |
| ↓ | переключает фиксацию **параллельно/перпендикулярно** наведённому ребру или плоскости — «anything that turns magenta»; направление и ребро/грань окрашиваются в magenta |
| Shift | фиксирует **активное** направление/плоскость (например, при рисовании по синей оси Shift удерживает синюю) |
| Shift+Alt (Win) / Shift+Cmd (macOS) | фиксация плоскости построения совпадает с плоскостью наведённой грани; для Rotate/Protractor Alt/Cmd «освобождает» центр, сохраняя плоскость |

Дополнительно документировано:

- часть инструментов (Circle, Rotate) фиксирует **плоскость**, а не направление — по цветной оси или нормали;
- **Esc** — начать заново (снять поставленную точку);
- **Alt/Cmd переключает режимы линейных привязок** (Line tool): «All Inferences On → All Inferences Off → Parallel and Perpendicular Only»; в режиме Off точечные привязки (On Face, Midpoint и др.) продолжают работать;
- стрелки и Shift в реальном SketchUp работают как **переключатели** (нажал — зафиксировал, нажал снова — снял), но это подтверждено только форумом ([313382](https://forums.sketchup.com/t/313382), [8091](https://forums.sketchup.com/t/8091), [18465](https://forums.sketchup.com/t/18465)), а не справкой; в справке — «hold down Shift».

### 3.5. Визуальная обратная связь

Документированные маркеры ([tips-and-tricks](https://help.sketchup.com/en/sketchup/tips-and-tricks), раздел «Inference Points»):

| Маркер | Значение |
|---|---|
| **зелёная окружность** | конец ребра (endpoint) |
| **синяя окружность** | середина (midpoint) |
| **синий ромб** | точка на форме/грани («points on shapes») |
| **красный крест (X)** | пересечение |
| **красный квадрат** | привязка вдоль линии или кривой (on edge) |

Дополнительно: у середины показывается «**light blue dot**» и ScreenTip «Midpoint»; линии осей окрашены по оси; параллель/перпендикуляр — magenta; линейные привязки дают временный пунктир; при фиксации линия становится «жирнее» и окрашивается (LayOut документирует обратное: пунктир → сплошная при фиксации — [using-inferences](https://help.sketchup.com/en/layout/using-inferences)).

Пробелы (не переносим дословно): формы и цвета маркеров для Origin/Component Origin/Center/Guide Point/On Line/On Section/Hidden Section/Perpendicular to Face/Extend Edge в тексте не описаны (только картинки); позиция подписи относительно курсора не документирована; правило показа «комбинированной» привязки не документировано.

### 3.6. Точность: Measurements box (VCB)

- Единицы задаются суффиксом: `10"`, `10'`, `10mm`, `10cm`, `10m` ([using-measurements-box](https://help.sketchup.com/en/using-measurements-box)).
- **Абсолютные координаты — в квадратных скобках, относительные — в угловых** (документировано для Move): «To enter global coordinates, use square brackets, such as `[3', 4', 5']` … To set relative coordinates (from the starting point of the move operation), use angle brackets, such as `<3', 4', 5'>`» ([moving-entities-around](https://help.sketchup.com/en/sketchup/moving-entities-around)).
- Многозначный ввод — через запятую (`8',20'`), допускаются отрицательные значения и частичное изменение (`,3'`); это документировано для прямоугольника ([drawing-basic-shapes](https://help.sketchup.com/en/sketchup/drawing-basic-shapes)).
- Углы — до 0,1° при измерении ([measuring-angles](https://help.sketchup.com/en/measuring-angles)); в настройках точность отображения углов — до трёх знаков.
- **Привязка к точности** — Model Info → Units: «Enable Length Snapping» («your drawing tool will snap to the closest unit at the level of precision indicated in the text box») и «Enable Angle Snapping» ([managing-units-measurement](https://help.sketchup.com/en/managing-units-measurement)).
- Координатный ввод документирован **только для Move**; разделители `;` и пробел нигде не документированы — наш парсер поддерживает их как совместимое расширение.

### 3.7. Сетка и пользовательские Snaps

**Сетки-привязки в SketchUp Desktop нет.** Полнотекстовый поиск по sitemap справки (771 URL) не даёт ни одной страницы про grid; в release notes 2024–2027 нет функции grid snap для вьюпорта. Есть только «Length/Angle Snapping» (§3.6) и сетка **LayOut** (отображение/печать, [document-setup](https://help.sketchup.com/en/layout/document-setup)). Найденная ранее в реестре команд 2026 строка «Grid Snapping» ([research §5.2](../research/01-sketchup-analysis.md)) документально не подтверждается — трактуем как внутреннюю/чужую команду и **не считаем паритетом**. Наша сетка — осознанное расширение.

**Snaps** (пользовательские точки сборки, появились в **2023.1**, не в 2025) — [help.sketchup.com/en/sketchup/snaps](https://help.sketchup.com/en/sketchup/snaps):

- Snap — пользовательская точка, добавляемая **внутрь группы или компонента**; выглядит как **диск**: лицевая сторона белая, обратная синяя; в центре — **Central Snap Point**; ориентацию задаёт **Alignment Direction** (нормаль диска).
- Создание: правка компонента → `Make/Edit Snaps`; диск следует за курсором, наводится на рёбра, грани, центры, середины, пересечения; первый клик — позиция, второй — ориентация (по умолчанию — синяя ось).
- Соединение: «Snaps attach to each other **front side to front side**»; при достаточной близости объект поворачивается по Alignment Direction **целевого** snap.
- К грани/ребру: лицевая сторона ложится на грань; к ребру — ориентация по последней грани, использованной для привязки.
- **Tractor beam** — Alt (Windows) подсвечивает ближайший подходящий snap и предпросмотр ориентации; в режиме правки Alt переворачивает ориентацию.
- **Stamp mode** Move tool — документирован по названию; включение (двойной Ctrl) подтверждено только форумом.
- Ruby API (2025.0): `Sketchup::Snap` с `#position`, `#direction` (нормаль), `#up` (поворот вокруг оси), `#set`; `Entities#add_snap(position, direction[, up])`; при соединении у двух snap **противоположные `direction` и совпадающие `up`**. Имени у snap в API нет — переименование не документировано.
- 2025.0: фиксация «параллельно» при работе со Snap по **↓**; пункт контекстного меню `Select > Connected by Snaps`.

## 5. Термины

| Термин | Значение |
|---|---|
| **Inference / привязка** | Правило, по которому положение курсора заменяется точкой или ограничивается прямой, выведенной из геометрии сцены или системы координат |
| **Кандидат** | Конкретный результат привязки: тип, точка, направление, сущность-источник, приоритет, уверенность |
| **Точечная привязка** | Кандидат, задающий точку (вершина, середина, центр, пересечение, на грани, на ребре, сетка) |
| **Линейная привязка (ограничение)** | Кандидат, задающий прямую, по которой движется точка (ось, параллель, перпендикуляр, касательная, продолжение) |
| **Комбинированная привязка** | Точечная + линейная одновременно (точка на пересечении ограничения и грани/ребра) |
| **Блокировка** | Принудительная фиксация текущей привязки (Shift) или конкретной оси/направления (стрелки) до клика или Esc |
| **Опорная точка (anchor)** | Точка, от которой инструмент строит (начало отрезка, база перемещения, центр окружности) |
| **Активный контекст** | Группа/компонент, внутри которого идёт редактирование; его локальные оси становятся осями inference |
| **Сущность (entity)** | Узел сцены, ребро, грань, окружность, направляющая или сетка, к которым относится кандидат |
| **Гистерезис** | Удержание последнего выбранного кандидата в течение короткого времени, чтобы подсказка не мерцала |

## 6. Функциональные требования

Приоритеты: **P0** — без этого итерация не имеет смысла; **P1** — нужно для паритета с SketchUp; **P2** — полировка/расширение.

### 6.1. Привязки к частям объектов

| # | Требование | Приоритет |
|---|---|---|
| R-1 | **Вершина (Endpoint).** Курсор в пределах толеранса от конца ребра привязывается к точной вершине. Маркер — **зелёная окружность** (документированная палитра SketchUp), подпись «Точка»/«Endpoint». Выше всех точечных привязок, кроме пользовательской точки сборки (v1.x). | P0 |
| R-2 | **Середина ребра (Midpoint).** Привязка к геометрической середине ребра; маркер — **синяя окружность / светло-синяя точка** (документировано), подпись «Середина»/«Midpoint». Середина дуги — отдельный тип (R-32). | P0 |
| R-3 | **Точка на ребре (On Edge).** Новый тип: курсор «скользит» по ребру (ближайшая точка ребра к лучу курсора), маркер — **красный квадрат** на подсвеченном ребре (документировано), подпись «На ребре»/«On Edge». Кандидат несёт направление ребра, поэтому построение можно продолжить вдоль него. Работает для одиночных рёбер, рёбер граней и проволочных цепей. | P0 |
| R-4 | **Точка на грани (On Face).** Привязка к пересечению луча с гранью; маркер — **синий ромб** (документировано), грань подсвечивается контуром, подпись «На грани»/«On Face». Работает с обеих сторон грани. | P0 |
| R-5 | **Центр (Center).** Центр окружности/дуги/полигона (из circle-fit) и центроид грани. Маркер — окружность с точкой (форма не документирована), подпись «Центр»/«Center». | P0 |
| R-6 | **Пересечение (Intersection).** Ребро×ребро, ребро×направляющая, направляющая×направляющая и **ребро×грань** (в SketchUp `Intersection` документирован как «line intersects another line **or face**»). Маркер — **красный крест (X)** (документировано), подпись «Пересечение»/«Intersection». Пары с общим концом не считаются пересечением (это вершина). Пересечения рёбер ищутся только среди пар, проходящих рядом с курсором (бюджет). | P0 |

| R-8 | **Продолжение ребра (`ExtendEdge`) и выравнивание от точки (`FromPoint`).** Два отдельных линейных типа: продолжение существующего ребра за его концы и пунктирная линия **от опорной/наведённой точки**. Пунктир `FromPoint` окрашивается цветом оси, если направление осевое (документированное поведение SketchUp). Кандидаты имеют пониженный приоритет и показываются только при отсутствии лучших; никогда не перекрывают мировые оси. | P1 |
| R-9 | **Начало координат и оси экземпляра группы/компонента (`Component Origin Point`).** При наведении на группу/компонент доступны её начало координат и точка вставки по умолчанию (маркер-кольцо с подписью имени контейнера) и три оси; при входе в контекст редактирования локальные оси становятся «мировыми» осями inference. | P1 |
| R-10 | **Привязка «сквозь» контейнеры и к скрытой геометрии.** По умолчанию — к геометрии внутри групп/компонентов без их открытия (подпись содержит имя контейнера). Скрытая геометрия включается **двумя способами:** постоянный режим отображения («Показать скрытую геометрию») и временный модификатор **Ctrl+Shift** (удержание) — он не конфликтует с Alt-циклом (R-23) и Shift-фиксацией (R-21). | P1 |
| R-11 | **Пользовательские точки сборки (Snaps, v1.x) — полная сборка.** Модель — как в SketchUp 2023.1+: диск с центральной точкой, передней (активной) и обратной сторонами, **Alignment Direction** (нормаль) и **up** (поворот вокруг оси), локальные координаты группы/компонента. Соединение «передняя к передней»: у двух snap направления противоположны, `up` совпадает. В объём v1.x входят: создание/правка/удаление, snap-to-snap, привязка к граням и рёбрам, **Stamp mode**, **tractor beam** (Alt подсвечивает ближайший snap и предпросмотр ориентации; в режиме правки Alt переворачивает ориентацию), `Select > Connected by Snaps`. В этой итерации — только модель данных и точка расширения в снимке сцены. | P2 |

### 6.5. Приоритеты и допуск

Порядок кандидатов: приоритет типа (см. Приложение A) → уверенность (близость к курсору) → глубина (ближе к камере) → экранное расстояние. Комбинированная привязка получает приоритет точки + 1.

Правила:

1. Точные геометрические точки (вершина, пересечение, середина, центр, пользовательская точка) всегда выше «скользящих» привязок (на ребре, на грани, продолжение).
2. Привязка к геометрии всегда выше сетки.
3. Оси выше продолжений и параллелей, но ниже точечных геометрических привязок.
4. При фиксации (Shift/стрелка) рассматриваются только кандидаты зафиксированного типа/направления; точечные привязки, несовместимые с фиксацией, подавляются.
5. Если два кандидата одного типа и приоритета совпадают по экранному расстоянию (± 1 px), выбирается ближайший по глубине; при равенстве — тот, чья сущность ближе к активному контексту (внутри редактируемого контейнера).
6. Толеранс — 8 px по умолчанию, настраивается 4–16 px; для сетки — отдельный радиус «прилипания» к узлу сетки (12 px), чтобы не дёргать курсор.
7. **Задержка над точкой повышает её приоритет** (документированное поведение SketchUp): если курсор задержался над кандидатом 250 мс, он получает +50 к приоритету до выхода из толеранса. Это позволяет выбирать «дальнюю» точку, не подводя курсор вплотную.
8. **Середина ребра vs «На ребре»:** без фиксации на середине ребра побеждает `Midpoint` (приоритет 700 против 450); если ребро зафиксировано (Shift на ребре или ↓), побеждает `OnEdge` — фиксация важнее точечной привязки.
9. **Не более двух подсказок одновременно:** на экране показываются лучший точечный и лучший линейный кандидат (если они совместимы); остальные доступны по Tab и не рисуются, чтобы не засорять вьюпорт.

### 7.1. Новые типы привязок

### 7.4. Снимок сцены

- `SnapSegment`, `SnapFace`, `SnapCircle` получают `SnapEntityRef`.
- Новые коллекции: `InstanceOrigins` (точка + имя + флаги осей), `UserSnaps` (v1.x), `Bounds`.
- Пользовательские Snap-точки в проектном файле хранятся как `position`, `direction`, `up` — **единичные векторы** (как в Ruby API `Sketchup::Snap`); угол вокруг `direction` не сериализуется, а вычисляется для UI.
- `InferenceSceneBuilder` заполняет ссылки при обходе иерархии; для инстансов компонентов — один проход на инстанс с `NodeId` инстанса.
- Кэш снимка остаётся в `ToolContext`; при включении режима «Показать скрытую геометрию» строится второй снимок (как сейчас с `includeHidden`).

### 7.5. Инструменты и ввод

- Общий вход: `ToolBase.ResolvePoint(...)` и `TransformToolBase.ResolvePoint(...)` возвращают не `Vector3d`, а `ToolPoint` (точка + кандидат), чтобы инструмент мог показать подсказку, учесть направление и подсветить источник.
- `ITool.TryApplyPoint(Vector3d point, bool relative)` — применить координату/точку к текущему шагу построения; используется VCB и координатным вводом. Реализовано: Line, Rectangle, Circle, Polygon, Arc (2/3 точки), Move (абсолютная цель или относительное смещение).
- `ToolContext` хранит состояние ввода: `LockModifiers` (стрелки) и `InferenceMode` (Alt); `ResolveSnapModifiers()` собирает их с Ctrl и передаёт инструментам.
- `ToolKey` расширяется: `Left, Right, Up, Down, Alt`; `KeyInput` получает `IsRepeat`.
- `ToolModifiers` уже содержит Shift/Ctrl/Alt — маршрутизация в UI добавлена.
- Отложено до W4: фиксация плоскости Shift+Alt, перебор кандидатов Tab, привязки Offset, настройки сетки в UI.

### 7.6. Модель оверлея

Результат для UI — `InferenceOverlay` (маркеры, линии, подписи, подсветка, индикатор блокировки), вычисляемый из `SnapResult` + `SnapRequest` в Core и рисуемый 2D-оверлеем вьюпорта. Это сохраняет чистоту движка и тестируемость: оверлей — чистые данные, проекция — во вьюпорте.

## 8. Алгоритмы

### 8.1. Точка на ребре (On Edge)

1. Отсев рёбер: экранный bbox проекции ребра расширяется на толеранс (существующий конусный предфильтр `IsWithinSnapRadius(midpoint, length/2)`).
2. Для каждого ребра — ближайшая точка к лучу (`InferenceMath.TryClosestPointOnLineToRay` с ограничением параметра отрезком).
3. Экранное расстояние ≤ толеранса → кандидат `OnEdge` с `Direction` = направление ребра, `Entity` = ребро, маркер `Dot`.
4. Дедупликация: кандидаты, совпадающие по точке (±0,5 px), схлопываются, побеждает ребро с меньшей глубиной.

### 8.2. Продолжение ребра и выравнивание от точки

Два типа, общий механизм:

- **`ExtendEdge`** — продолжение существующего ребра за его концы. Источник — ребро, «горячее» под курсором, или ребро, на котором лежит опорная точка `Anchor`.
- **`FromPoint`** — выравнивание от точки: линия проходит через опорную/наведённую точку в направлении, заданном ребром (или осью); пунктир окрашивается цветом оси, если направление осевое.

Алгоритм:

1. Выбрать анкер: (а) `Anchor`, если он лежит на ребре; (б) ближайшая «горячая» вершина/ребро под курсором. При нескольких наведённых точках приоритет у **последней задержавшейся** (dwell, §6.5 п. 7) — задокументированное в SketchUp правило анкера отсутствует (§3.3), поэтому фиксируем своё.
2. Направление — направление ребра; линия проходит через анкер.
3. Кандидат: точка — ближайшая на линии к лучу; `ConstraintLine` — для пунктира; видимая часть — от анкера до ±5 длин ребра (дальше не рисуем).
4. Не создаётся, если направление совпадает с мировой осью (ось уже даёт кандидата) или если от того же ребра уже есть лучший `Parallel`.
5. `ExtendEdge` приоритетнее `FromPoint` на 10; оба ниже осей.

### 8.3. Сетка

1. Плоскость: у 2D-инструментов — `DrawingPlane`; у Move — плоскость перемещения; у прочих — плоскость, перпендикулярная взгляду, проходящая через опорную точку.
2. Луч → точка на плоскости; координаты квантуются: `round((p - origin) / step) * step + origin`.
3. Кандидат принимается, если его экранное расстояние ≤ радиусу прилипания сетки (12 px). Иначе сетка не вмешивается.
4. При фиксированной оси квантуется только координата вдоль оси, остальные — из текущей точки.

### 8.4. Числовой ввод координат

1. Грамматика: `[x, y, z]` — абсолютные координаты, `<dx, dy, dz>` — относительно опорной точки (оба синтаксиса документированы в SketchUp). Совместимое расширение — `;` и пробел как разделители компонент (`x; y; z`, `x y z`). Разделитель дробной части — `.` или `,`; запятая как разделитель компонент работает, если не является десятичной.
2. Два компонента допускаются только при известной плоскости построения (z берётся из плоскости); иначе — ошибка «нужно три координаты».
3. Единицы — единицы сцены, допускаются суффиксы (`mm`, `cm`, `m`).
4. Применение — через `ITool.TryApplyPoint`; для Move — как целевая точка, затем коммит команды.
5. Ошибка ввода показывается в статус-строке, построение не меняется.

### 8.5. Блокировки

Состояние (`SnapSession`):

```text
InferenceMode: All (по умолчанию) → PointsOnly (Alt) → ParallelPerpendicularOnly (Alt) → All
Lock: None
    | ShiftHeld       — активное направление/плоскость, снимается при отпускании Shift
    | AxisX | AxisY | AxisZ   — переключатель (стрелка)
    | Magenta         — параллель/перпендикуляр (↓), переключатель
    | FacePlane       — плоскость наведённой грани, пока удержаны Shift+Alt
```

Переходы:

- **Shift (удержание)** фиксирует активное направление/плоскость; отпускание снимает. Если активна стрелочная фиксация, Shift её не отменяет, а уточняет (например, плоскость).
- **Стрелка** фиксирует ось/направление по таблице §3.4; та же стрелка снимает, другая переключает; фиксация сохраняется после отпускания клавиши. **↓** фиксирует параллель/перпендикуляр к наведённому ребру (magenta).
- **Shift+Alt** фиксирует плоскость построения по плоскости наведённой грани (пока удержаны обе); для Rotate/Protractor Alt «освобождает» центр.
- **Ctrl+Shift (удержание)** временно включает скрытую геометрию (R-10); на фиксацию не влияет.
- **Alt** (без Shift) переключает режим линейных привязок `All → PointsOnly → ParallelPerpendicularOnly`; режим показывается в статус-строке.
- **Клик/Enter** применяет и снимает фиксацию; **Esc** снимает без применения и позволяет начать шаг заново.
- Пока фиксация активна, движок получает `Lock` и возвращает только совместимые кандидаты: при фиксации направления — линейные ограничения этого направления (и точки, лежащие на нём); при фиксации плоскости — точки/линии в этой плоскости.

Конфликт с существующей навигацией: сейчас Shift+ЛКМ — панорама ([TransformToolBase.cs](../../src/SmetaNA.Core/Tools/Editing/TransformToolBase.cs)); по §3.4 Shift должен фиксировать привязку. Решение: панорама — СКМ или пробел+ЛКМ; Shift+ЛКМ остаётся панорамой только при отсутствии активного построения.

### 8.6. Гистерезис

Хранить последний принятый кандидат и время. Новый кандидат замещает удержанный, если: (а) его приоритет выше, и он в пределах толеранса; (б) он ближе к курсору более чем на 2 px; (в) удержанный кандидат вышел за 1,5× толеранса. Иначе оставить удержанный и пометить `IsSticky`.

### 8.7. Производительность

Сохранить существующие отсечки (конусный предфильтр, 256 сегментов для пересечений, 64 направления параллелей) и добавить:

- отсев рёбер/граней по экранному bbox до точных вычислений;
- лимит кандидатов на тип (например, 8 ближайших рёбер на OnEdge);
- кэш проекций вершин на кадр (курсор двигается — камера обычно нет);
- бюджет времени: при превышении 8 мс — прекращать сбор кандидатов низких приоритетов (сетка, продолжения), не блокируя UI.
- Измерять: `SnapResult.SolveMilliseconds` (диагностика) + смоук-тест на 200k рёбер.

## 10. DoD и приёмочные сценарии

1. **S1. Вершина.** Куб; инструмент «Линия»; курсор в 6 px от вершины → зелёная окружность и подпись «Точка», клик даёт точку ровно в вершине (проверка координат с точностью 1e-6 мм).
2. **S2. Ребро.** Курсор над серединой ребра → «На ребре», точка лежит на ребре (расстояние до ребра ≤ 1e-6 мм); при движении вдоль ребра точка не сходит с него.
3. **S3. Блокировка оси.** Shift (удержание) фиксирует направление «Параллельно ребру», отпускание снимает; стрелка → фиксирует красную ось как переключатель и сохраняется после отпускания; ввод `100` даёт отрезок ровно 100 мм по X.
4. **S4. Абсолютные координаты.** Ввод `[10, 20, 0]` в Line ставит первую точку в (10,20,0) мм; ввод `30, 20, 0` — вторую; длина 20 мм по X.
5. **S5. Относительные координаты.** От точки (10,20,0) ввод `<0, 5, 0>` даёт (10,25,0).
6. **S6. Move по координатам.** Выбрать объект, Move, ввести `0, 0, 50` → объект перемещён на 50 мм по Z одной записью undo; повторный ввод не создаёт «пустую» команду.
7. **S7. Сетка.** Включить сетку 10 мм; углы прямоугольника ложатся на узлы; при наведении на вершину куба (не на узле) побеждает вершина.
8. **S8. Пересечение.** Два пересекающихся ребра → «Пересечение» в точке пересечения, приоритет выше «На ребре».
9. **S9. Внутри группы.** Геометрия внутри группы: привязка работает без открытия группы, подпись содержит имя группы; режим «Показать скрытую геометрию» и временное Ctrl+Shift добавляют скрытые объекты в снимок.
10. **S10. Начало координат компонента.** Наведение на инстанс компонента даёт его origin/оси; при входе в контекст оси становятся локальными.
11. **S11. Производительность.** Сцена 200k рёбер: P95 обработки движения ≤ 8 мс; FPS ≥ 30; отсутствие «залипаний» UI.
12. **S12. Локализация.** Все подписи и подсказки переключаются RU/EN без перезапуска.
13. **S13. Доступность.** Все операции достижимы с клавиатуры; фокус VCB не теряется; подписи читаются скринридером (текстовые, не только цвет).
14. **S14. Переключатель координат контекста.** Внутри компонента ввод `[10, 0, 0]` трактуется локально; переключение в статус-строке на «мировые» применяет ту же строку как мировую координату; переключение не сбрасывает текущий шаг построения.
15. **S15. Середина vs ребро.** Курсор ровно на середине ребра → «Середина»; Shift на ребре или ↓ → «На ребре», точка остаётся на ребре при движении вдоль него.

Юнит-тесты (xUnit, по образцу `SmetaNA.Core.Tests/Inference*`): каждый тип привязки — на кубе/ребре/окружности; приоритеты; блокировки; сетка; парсер координат; ссылки на сущности; гистерезис; бюджет времени на синтетической сцене.

## 13. Принятые решения (2026-11-05)

### 13.1. Объём и модификаторы

- Блокировки: гибрид — стрелки-переключатели, Shift — удержание.
- Координаты контекста: переключатель в статус-строке, по умолчанию локальные.
- Сетка и `Length Snapping`: обе, независимо, выключены по умолчанию.
- Середина vs «На ребре»: без фиксации — середина, при фиксации ребра — ребро.
- Скрытая геометрия: режим отображения + `Ctrl+Shift` (удержание).
- Snaps в v1.x: полная сборка (snap-to-snap, Stamp, tractor beam).

### 13.2. Ранее открытые вопросы — закрыты

1. **Подписи на экране** — показываются постоянно, пока активен инструмент; отключаются настройкой «Показывать подписи».
2. **Комбинированные подсказки** — одновременно на экране не более **двух** кандидатов: лучший точечный + один линейный; остальные доступны по Tab.
3. **Временная скрытая геометрия** — `Ctrl+Shift` (удержание). В Move после старта операции Ctrl управляет копией, `Ctrl+Shift` — только подсветкой.
4. **Шаг сетки по умолчанию** — **10 единиц сцены** (10 мм в шаблоне «мм», 10 см в «см», 10 м в «м»); пресеты показываются в текущих единицах.
5. **Приоритет W5 (Snaps)** — сразу после W4; сдвигается, только если появится более приоритетная задача v1.x.
6. **Сериализация Snap-точки** — `position`, `direction`, `up` как единичные векторы (как в Ruby API); угол вокруг `direction` не хранится, а вычисляется для UI.

### 13.3. Уточнения, принятые при реализации W1–W3

- **Клавиатура и автоповтор.** В Avalonia нет `KeyEventArgs.IsRepeat`, поэтому `ViewportView` ведёт набор `_heldToolKeys` и снимает клавишу по `KeyUp`; иначе удержание стрелки/Alt крутило переключатель осей и режимы.
- **Отказ инструмента от координат.** Если инструмент не может применить точку из VCB (например, нулевой радиус), ввод возвращает `VcbError.NotApplicable` вместо молчаливого игнорирования; строка ошибки переведена (RU/EN).
- **VCB сам определяет тип ввода.** Одно и то же поле принимает число (длина/угол по `VcbKind`) и координаты `[x,y,z]` / `<dx,dy,dz>`; при неоднозначности приоритет у координат, а скалярные подсказки остаются доступны.
- **`TryApplyPoint(point, relative)`** реализован в Line, Rectangle, Circle, Polygon, Arc2, Arc3 и Move; `MoveTool.VcbKind` остаётся `Length`, но координаты принимаются независимо от палитры.
- **Transform-привязки.** В Move/Rotate/Scale база операции берётся из `ResolveSnapPoint` один раз при старте drag, цель Move пересчитывается через `TryUpdateOperationAt`; инструменты публикуют `CurrentSnap` для оверлея и до нажатия (hover).
- **Тесты рядом с геометрией.** Появление `OnEdge` изменило ожидания старых тестов: точки в пределах допуска от ребра теперь притягиваются — ожидания сдвинуты в чистые области сцены, а тесты комбинированных привязок проверяют наличие кандидата, а не только `Best`.

### 13.4. Уточнения, принятые при реализации W4

- **Снимок сцены — один на все инструменты.** `ToolContext.SnapScene` учитывает постоянный режим и Ctrl+Shift; выбор грани (`TryPickFace`) использует тот же флаг. Составной снимок собирается только через `InferenceScene.WithExtra` — иначе терялись середины дуг и начала координат контейнеров (найденный дефект W1).
- **Ctrl без Shift — только точечные привязки,** Ctrl+Shift — скрытая геометрия (не сужает категории); панорама Shift+ЛКМ не срабатывает при Ctrl или Alt, иначе модификаторы привязок и фиксация плоскости были бы недостижимы.
- **Сетка ниже осей.** Приоритет сетки (120) намеренно ниже осей (300): вблизи осей побеждает ось, сетка добирает остальное. Допуск сетки — 12 px (больше общего 8 px), чтобы узлы не «проскакивали».
- **Настройки** — `InferenceSettings` (толеранс 2–40 px, шаг сетки, категории, подписи, скрытая геометрия, привязка длины) в `%APPDATA%/SmetaNA/settings/inference.json` с версией схемы; неизвестная/битая версия даёт значения по умолчанию. В меню «Вид» вынесены переключатели скрытой геометрии, сетки, подписей и привязки длины, а также пункт циклического шага сетки (0,1 → 1 → 10 → 100).
- **Привязка длины (R-14.1)** применяется после разрешения точки: длина от опорной точки округляется до `LengthPrecision` с сохранением направления; точные геометрические привязки (вершина, середина, пересечение, центр, начало координат, узел сетки) не округляются — иначе округление «отрывало» бы точку от вершины.
- **Антимерцание** живёт в движке: запрос несёт `PreviousBest`/`PreviousBestAgeMs`, инструмент считает возраст лучшего типа через `Stopwatch`. Удержание — только пока предыдущий кандидат в 1,5× толеранса; перехват — при приоритете на 100 выше или на 2 px ближе.
- **Tab** перебирает кандидатов (`SnapResult.WithBest`), индекс живёт в `ToolContext` и сбрасывается движением указателя; после нажатия привязка пересчитывается синтетическим hover-событием.
- **Shift+Alt** фиксирует плоскость последней наведённой грани (`DrawingToolBase.UpdatePlaneLock`): точка строится в этой плоскости, перехват кандидата Shift при этом не включается.
- **Ограничение производительности на 500k.** Бенчмарки push/pull-наведения и построения батча 500k треугольников на текущей машине выходят за бюджеты и на baseline-коммите — это фоновая деградация окружения, а не регрессия волны; бюджеты inference на 200k рёбер остаются в бэклоге.

### 13.5. Уточнения, принятые при реализации W5a (пользовательские Snaps)

- **Кадр.** `SnapFrame` (Geometry): позиция, нормаль диска `Direction`, `Up`; при создании векторы нормализуются, `Up` ортогонализуется нормали, вырожденная нормаль отвергается. Базис правый: `Right = Up × Direction`, столбцы `ToTransform()` — R/U/D.
- **Хранение.** `SnapNode : SceneNode` держит кадр в **локальных** координатах: snap переезжает вместе с группой/компонентом, в снимок попадает `WorldFrame`. Сериализуется в проектный файл (`userSnap` + `snap.position/direction/up`), копируется клонировщиками (обычным и M6-зеркалом).
- **Соединение.** `SnapFrame.FrontToFront(moving, target)`: нормаль подвижного становится противоположной нормали цели, `up` совпадает, позиция — целевая. `SnapQuery.AreConnected` проверяет это с допуском 1e-6.
- **Привязка.** Движок отдаёт `SnapType.SnapPoint` с приоритетом 950 (выше вершины) и заполненным `SnapCandidate.Frame`; фильтр `SnapPoints` отключает их. `SnapEntityRef.Kind = UserSnap` и `DisplayName` контейнера — для подписи и подсветки.
- **Поиск.** `SnapQuery.FindInScene/FindIn` обходит сцену и содержимое определений компонентов (общие узлы определения возвращаются один раз) — основа для пункта `Connected by Snaps`.
- **Ограничение.** Ориентация пока не участвует в Move/Stamp: инструменты и диск в вьюпорте — следующая часть W5.

### 13.6. Уточнения, принятые при реализации W5b (инструмент и диск)

- **Инструмент «Точка сборки»** (`SnapTool : DrawingToolBase`, `tool.snap`, клавиша **K**): первый клик — центр диска через обычные привязки (вершины, рёбра, грани, другие snap'ы), второй клик — ориентация по направлению от центра к курсору; **Enter** завершает с нормалью по синей оси, **Esc** отменяет шаг (сцена не меняется).
- **Одна запись истории:** snap создаётся только на завершающем шаге (`AddNodeCommand`), поэтому Esc и повторный клик не оставляют мусора в `UndoStack`.
- **Контейнер:** snap добавляется в родителя узла грани под курсором (внутрь группы/компонента, если клик по их геометрии), иначе — в корень сцены.
- **Отображение:** вьюпорт рисует диск 2D-оверлеем — проекция осей кадра задаёт эллипс, лицевая сторона белая, обратная синяя (по знаку `Direction · Forward` камеры), в центре точка; диаметр постоянный на экране (11 px). Snap'ы видны постоянно, скрытые контейнеры учитываются тем же режимом, что и привязки.
- **UI-регистрация:** глиф `ToolIconId.Snap` (диск с точкой), кнопка в группе «Рисование», лента, каталог горячих клавиш и локализация RU/EN (`Tool.Snap`, `Tool.Hint.Snap`); контрактные тесты палитры/иконок обновлены (25 глифов, 28 команд реестра).

### 13.7. Уточнения, принятые при реализации W5c (snap-to-snap в Move)

- **Совмещение кадров.** `SnapFrame.DeltaTo(target)` даёт поворот + перенос: оси и позиция источника переходят в оси и позицию цели (базис считается без трансляции, иначе перенос цели учитывался дважды).
- **Соединение.** Move берёт кадр базы (snap, на который попал первый клик) и кадр цели, строит `FrontToFront(source, target)` и применяет `source.DeltaTo(attached)`; `WorldDelta` — полноценная аффинная матрица, поэтому предпросмотр, перемещение грани (через склейку) и объекта работают без изменений.
- **Комбинированные кандидаты.** При продвижении линейной привязки через совпавшую точку (`PromoteCombined`) кадр и источник точки теперь копируются в комбинированный кандидат: у snap'а на оси лучший кандидат — «ось + точка», и без переноса кадра Move не видел ориентацию.
- **Отмена ориентации.** Ручное перетаскивание в плоскости экрана и координатный ввод VCB сбрасывают доворот: они задают только смещение. `IsNoOp` учитывает ориентацию отдельно (чистый поворот без смещения — не пустая операция).
- **Диагностика.** `MoveTool.SourceSnapFrame` отдаёт кадр захваченной точки — пригодится для предпросмотра ориентации и tractor beam (W5d).

### 13.8. Уточнения, принятые при реализации W5d (правка, удаление, tractor beam)

- **Правка ориентации.** Клик инструментом «Точка сборки» по существующему snap'у не создаёт новый диск, а начинает правку: центр берётся из узла, второй клик применяет `SetSnapFrameCommand` (одна запись истории). Кадр переводится из мира в локальные координаты узла через обратную трансформацию.
- **Alt-переворот.** При выборе ориентации удержание Alt инвертирует направление — диск встаёт обратной стороной (документированное поведение режима правки Snap'ов).
- **Удаление.** Delete при наведении на snap удаляет узел командой истории; при активном шаге ориентации Delete не трогает сцену.
- **Tractor beam.** Удержание Alt во вьюпорте подсвечивает ближайший в радиусе 80 px диск: кольцо + три оси кадра (нормаль синяя, up зелёная, третья красная) + имя. Срабатывает до привязки, работает и без активного инструмента; перерисовка по нажатию/отпусканию Alt.
- **Общий помощник.** `SceneNode.WorldTransform()` переехал в базовый узел (раньше жил только в `AnnotationNode`), им пользуются snap-инструмент и оверлей — дублирование убрано.

### 13.9. Закрытие хвостов inference (2026-11-05)

- **Stamp mode.** `TransformToolBase.EnableStamp()` превращает текущий перенос объекта в штамп: копия добавляется при фиксации, оригинал остаётся. Включается нажатием Ctrl **во время** перетаскивания (Ctrl при старте, как и раньше, сразу даёт копию), недоступен в режиме правки грани. Тесты: оригинал на месте, копия снесена на дельту, undo убирает её; `EnableStamp()` для грани возвращает `false`.
- **Connected by Snaps.** `SnapQuery.FindConnected(scene, snap)` возвращает snap'ы, соединённые «лицевая к лицевой» (мировые кадры, допуск 1e-6). Логика покрыта тестами; пункт контекстного меню пока не выведен — в приложении нет мультивыбора (`ToolSelection` хранит один узел), поэтому выбор «всех связанных» потребует сначала расширить модель выбора.
- **Shape inference (R-35)** для прямоугольника: почти квадрат (отклонение ≤2 %) доводится до точного квадрата, почти золотое сечение — до точной пропорции; подсказка «Квадрат»/«Золотое сечение» рисуется в предпросмотре через `ToolPreviewLabel.LocalizationKey` (Core не хранит переводы). Отличие от SketchUp: пропорция фиксируется автоматически в пределах допуска, отдельного Shift-удержания нет — Shift в приложении занят панорамой кадра.
- **Производительность 200k рёбер.** Бенчмарк `InferencePerformanceBenchmarkTests` (сетка 200k сегментов, медиана из 12 запросов) с бюджетом **8 мс** (S11). История: ≈180–250 мс → ≈130 мс (дешёвый предфильтр на концы/середину, вынос `WorldTolerance` из цикла пар, AABB-отсев пар, `SegmentsArray`) → **1,7 мс** после BVH по AABB рёбер и граней (`InferenceSpatialIndex`): выборка «рядом с лучом» заменяет полные проходы, отсев консервативен (надмножество прежнего предфильтра), индекс кэшируется на снимке и не зависит от камеры.
- **Настройки в UI.** В меню «Вид» добавлены циклические пункты «Толеранс привязки» (6 → 8 → 12 px) и «Категории привязок» (все → точки и оси → без осей → только геометрия); значения уходят в `InferenceSettings` и сохраняются в `inference.json`. Кастомные наборы категорий из файла распознаются: подпись показывает «все», если набор не совпал с пресетом.
- **Гигиена репозитория:** `data/temp/` (скриншоты багрепортов и варианты макетов) добавлен в `.gitignore`.

## Приложение B. Клавиши и модификаторы

| Ввод | Действие |
|---|---|
| Shift | **Удерживать** — фиксация активного направления/плоскости; отпустить — снять (документировано) |
| → | Красная ось (X); переключатель |
| ← | Зелёная ось (Y) |
| ↑ | Синяя ось (Z) |
| ↓ | Параллель/перпендикуляр к наведённому ребру или плоскости («magenta») |
| Shift+Alt | Плоскость построения = плоскость наведённой грани; для Rotate/Protractor Alt освобождает центр |
| Alt | Цикл режимов: все привязки → только точечные → только параллель/перпендикуляр (документировано для Line) |
| Ctrl+Shift | **Удерживать** — временно показать скрытую геометрию (R-10) |
| Tab | Следующий кандидат (при нескольких) |
| Esc | Снять фиксацию / начать шаг заново |
| Enter | Применить ввод VCB / завершить шаг |
| `[x, y, z]` | Абсолютные координаты (документировано) |
| `<dx, dy, dz>` | Относительные координаты (документировано) |
| `x; y; z`, `x y z` | Наше расширение синтаксиса |
| СКМ / пробел+ЛКМ | Панорама (освобождает Shift для фиксации) |
