## 2. Выбор установщиков

### Windows: Inno Setup (не MSIX)

**Требования к инструменту сборки:** Inno Setup ≥ 6.3 (`smetana.iss` использует `ArchitecturesAllowed=x64compatible`; проверено на 7.1.0, ISCC ставится per-user без админа). Внимание на лицензию: сборки Inno Setup 6.3+ печатают «Non-commercial use only» — перед коммерческим релизом проверить условия лицензии Inno Setup для коммерческого использования сборочного ПО (или выбрать замену — WiX/NSIS) — это инструмент сборки, лицензия не влияет на распространяемый продукт, но регулирует саму сборку.

| Критерий | Inno Setup 6 | MSIX |
|---|---|---|
| Установка без администратора (школьные ПК) | да (`PrivilegesRequired=lowest`, в `%LOCALAPPDATA%\Programs`) | требует доверия сертикату издателя (sideload) |
| SmartScreen для нового издателя | обычный код-сигнинг + репутация со временем | тот же сертификат, но + настройка доверия на машинах |
| Мультиязычный мастер (RU/EN), страница EULA | встроено | ограничено |
| Тихая установка в аудитории | `/SILENT`, `/NORESTART` — массовый деплой | `Add-AppxPackage` скриптом |
| Работа с файлами рядом с приложением (нативные `runtimes/`, шаблоны) | обычная файловая система | виртуализация файловой системы MSIX усложняет |
| Распространение напрямую с сайта (не через Store) | штатно | Store не подходит (продукт продаётся напрямую; R4) |
| Цена | бесплатно (Inno Setup License разрешает коммерческое использование) | — |

**Вывод:** Inno Setup. MSIX отклонён: зависимость от доверия sideload-сертификату на школьных ПК без администратора и виртуализация файловой системы — риск для нативных библиотек и шаблонов. Спецификация: [deploy/windows/smetana.iss](../deploy/windows/smetana.iss) (per-user, x64, EULA-страница, RU/EN, подпись exe и деинсталлятора через `/DSign`).

### Linux: deb (основной), AppImage (запасной)

| Критерий | deb (dpkg-deb) | AppImage |
|---|---|---|
| Эталонная платформа (Ubuntu 22.04+) | нативно: `apt install ./smetana_*.deb` | работает, но требует `libfuse2` (на Ubuntu 24.04 не установлен по умолчанию — типовая проблема в аудиториях) |
| Системная интеграция (.desktop, меню, иконки, ассоциации `.smeta`) | штатно | хуже: каждый запуск как «скачанный файл» |
| Зависимости (libGL, libX11, fontconfig) | описаны в `control`, ставятся apt автоматически | пользователь разбирается сам |
| Портативность без прав / «распаковал и запустил» | нет | да |
| Воспроизводимость сборки | `dpkg-deb` везде, без внешних тул | нужны appimagetool и спецсборки |

**Вывод:** deb — основной формат (самая массовая аудитория — Ubuntu 22.04+ в школах/вузе, простая установка, контроль зависимостей). AppImage — запасной формат «переносной» поставки (для дистрибутивов без dpkg и для флешки); собирается из того же среза `artifacts/publish/linux-x64` и не требует отдельной логики приложения. **Собирать deb на glibc 2.35 (Ubuntu 22.04 или контейнер `ubuntu:22.04`)** — иначе зависимость `libc6` получится новее минимальной поддерживаемой.

## 3. Стратегия публикации приложения (publish)

Решения и обоснования (реализация — [deploy/publish.ps1](../deploy/publish.ps1)):

| Параметр | Решение | Зачем |
|---|---|---|
| `--self-contained true` | **да** | Школьные ПК без установленного .NET; не тянем рантайм с сайта Microsoft (R4); предсказуемая работа. Стоимость: ~225 МБ срез (~90 МБ в сжатом установщике) — приемлемо |
| `PublishSingleFile=false` | **не single-file** | Нативные библиотеки Manifold/lib3mf/Angle обязаны лежать файлами (`runtimes/<rid>/native/` и рядом со сборкой — см. §4); single-file усложняет извлечение, чаще триггерит ложные срабатывания антивирусов и затрудняет обновления |
| `PublishTrimmed=false` | **без trimming** | Avalonia использует рефлексию/XAML и ресурсы; trimming их ломает |
| `PublishReadyToRun=true` | **да** (отключаемо `-NoReadyToRun`) | Холодный старт ≤ 5 с (DoD §5.1) на слабых ПК (UHD 620); R2R сокращает время JIT. Стоимость: +размер среза |
| Конфигурация | `Release`, `net10.0` | Из [Directory.Build.props](../Directory.Build.props) |
| Платформы | `win-x64`, `linux-x64` | Спека §2 (Windows 10/11 x64 и Ubuntu 22.04+ x64) |

**Минимальная конфигурация (8 ГБ RAM / Intel UHD 620, DoD §5.6)** на параметры публикации не влияет: самодостаточный рантайм не требует памяти сверх приложения, R2R снижает нагрузку на старте; бюджет FPS закрывается ядром рендера (спики `spikes/`), а не установщиком. Замеры производительности релиза — на этой конфигурации (чек-лист §10).

Версия берётся из `Directory.Build.props` (`<Version>`) и может быть переопределена `-Version`; для релиза значение перекрывается при publish (`-p:Version=`), тег git — `v<версия>`.

## 4. Нативные зависимости и раскладка пакета

Нативные библиотеки **не коммитятся в git** и воспроизводятся скриптами:

| Компонент | Версия | Лицензия | Откуда | Куда в репозитории |
|---|---|---|---|---|
| Manifold (CSG, C API `MANIFOLD_CBIND`) | 3.5.4 | Apache-2.0 | `spikes/Spike.Manifold/build-native.ps1` (сборка из исходников; Linux — cmake-инструкция в `src/SmetaNA.Manifold/README.md`) | `src/SmetaNA.Manifold/runtimes/<rid>/native/` (через `fetch-native.ps1`) |
| lib3mf (формат 3MF) | 2.5.0 | BSD-2-Clause | `src/SmetaNA.Formats/ThreeMf/native/fetch-lib3mf.ps1` (официальный релиз 3MF Consortium, проверка SHA-256) | `src/SmetaNA.Formats/ThreeMf/native/<rid>/` |
| oneTBB (опц., ускорение Manifold ≈2×) | 2022.3.0 | Apache-2.0 | статически линкуется в Manifold при `MANIFOLD_PAR=ON` | — |

Раскладка в пакете (задача 6.7) — NuGet-схема `runtimes/<rid>/native/` **плюс** копии в корень каталога приложения:

```
SmetaNA/                       (или /usr/lib/smetana/)
  SmetaNA.EditorUI(.exe)       — приложение и managed-сборки
  manifoldc.dll, manifold.dll  — корень: DllImport("manifoldc") ищет рядом со сборкой
  lib3mf.dll                   — корень: резолвер Lib3mfNative ищет рядом со сборкой
  runtimes/win-x64/native/     — те же библиотеки по NuGet-раскладке (lib3mf ищет и здесь)
  docs/legal/                  — EULA, privacy, third-party-licenses
  SHA256SUMS.txt
```

`deploy/publish.ps1` раскладывает библиотеки в оба места и в строгом режиме (`-RequireNatives`) падает, если чего-то нет; без флага — предупреждает (удобно для CI, где нативники собираются отдельно). `lib3mf.dll`/`lib3mf.so` находит собственный резолвер (`Lib3mfNative`: каталог сборки → `runtimes/<rid>/native/`); Manifold — стандартный `DllImport` (нужен корень каталога).

## 5. Код-сигнинг (заготовка)

Реализация — [deploy/sign.ps1](../deploy/sign.ps1); секреты только в переменных окружения (`SMETANA_SIGN_*`), в git не попадают.

**Windows:**
1. Сертификат code signing (для минимизации SmartScreen желателен EV/квалифицированный сертификат УЦ, входящий в программу доверия; допустим обычный OV).
2. `signtool sign /fd SHA256 /td SHA256 /tr <timestamp RFC3161> ...` — подписываются `SmetaNA.EditorUI.exe` и все `*.dll` среза, затем сам установщик и деинсталлятор (`SignedUninstaller=yes` в .iss, собирается с `/DSign`).
3. `signtool verify /pa /all` — контроль.
4. Timestamp обязателен: подпись должна работать после истечения сертификата.

**Linux:**
1. GPG-ключ издателя (публичный ключ — на сайте, R4: сайт в РФ).
2. `gpg --detach-sign --armor` → `<пакет>.deb.asc`; `SHA256SUMS-linux64.txt` подписывается тем же ключом.
3. Инструкция по проверке подписи — на странице скачивания (`site/`).

**Статус заготовки:** скрипты готовы и печатают точные команды; подключение сертификата — заменить переменные окружения на реальные значения, без правок кода.

## 6. SBOM и инвентаризация лицензий

Политика (спека §4, R7): **только MIT / Apache-2.0 / BSD / Boost**. Генерация и сверка — [deploy/new-sbom.ps1](../deploy/new-sbom.ps1): `dotnet list package --include-transitive` + nuspec-метаданные + классификация текстов лицензий из пакетов + ручные записи для ненуветных компонентов. Выпуск релиза блокируется кодом выхода 2 при нарушении.

Фактический статус на 2026-10-23 (детали и полный список — [legal/third-party-licenses.md](legal/third-party-licenses.md)):

- **Нарушений политики нет.** Все NuGet-зависимости — MIT (Avalonia 12.x, Silk.NET 2.23, SkiaSharp, HarfBuzzSharp, MicroCom, Tmds.DBus, Microsoft.Extensions) или Apache-2.0 (xunit — только dev); ненуветные — Apache-2.0 (Manifold 3.5.4, oneTBB) и BSD-2-Clause (lib3mf 2.5.0).
- **Два флага NOASSERTION** (нет SPDX-выражения в nuspec, лицензия задана файлом) — проверены вручную по текстам лицензий в пакетах, соответствие политике подтверждено: `Avalonia.Angle.Windows.Natives` (BSD-3-Clause, ANGLE Project Authors) и `Microsoft.DotNet.PlatformAbstractions` (MIT, .NET Foundation). Для релиза достаточно держать `third-party-licenses.md` в пакете (требование воспроизведения уведомлений BSD).
- `xunit.abstractions 2.0.3` (только dev-зависимость, в продукт не поставляется) — метаданные `licenseUrl`, текст — Apache-2.0.

SBOM публикуется вместе с релизом (CycloneDX 1.5, `sbom.cdx.json`).

## 7. Офлайн-режим и аудит (R4, DoD §5.8)

Требование: приложение **полностью офлайновое** — без телеметрии, без обязательной сети, покупка/активация/работа без VPN из России.

Аудит — [deploy/verify-offline.ps1](../deploy/verify-offline.ps1):

1. **Статический аудит исходников `src/`** (комментарии отбрасываются): сетевые API (`HttpClient`, `WebRequest`, сокеты, DNS, gRPC, почта, загрузка файлов, телеметрия) — срабатывание блокирует релиз (код 2).
2. **Строковое сканирование среза** (`-PublishedDir`) на URL в сборках — информационно (лицензионные тексты и ссылки на документацию допустимы, allowlist в скрипте).

**Результат аудита 2026-10-23: сетевых вызовов в `src/` не найдено (0 срабатываний).** Лицензирование ([SmetaNA.Licensing](../src/SmetaNA.Licensing)) полностью офлайново: подписанные ключи и токены активации (ECDsa), node-lock по отпечатку устройства, локальный леджер активаций, чеки деактивации и списки отзыва — обмен файлами/без сети. Триал — локальный. DoD §5.8 (активация и работа ≥ 30 дней без сети) обеспечено архитектурно: никакого «дозвона» к серверу лицензий нет и не планируется (R4).

## 8. Автообновления — заготовка под v1.x (M12)

В v1.0 обновления **ручные**: скачать новый установщик с сайта, установить поверх (настройки и лицензия сохраняются). Автообновления — v1.x; контракт-заготовка:

1. **Манифест обновлений** на сайте (хостинг в РФ, R4): `https://smetana.example.ru/updates/manifest.json` — версия, канал (stable/beta), URL и SHA256 артефактов, минимальная версия, текст изменений.
2. **Подпись манифеста** тем же ключом, что и лицензии (Ed25519/ECDSA; публичный ключ вшивается в приложение) — защита от подмены.
3. **Проверка по требованию** (меню «Проверить обновления») и раз в сутки в фоне; при отсутствии сети — молча продолжает работу (офлайн-режим не деградирует).
4. **Установка** — отдельным процессом-апдейтером после явного согласия пользователя; никогда не в фоне без спроса (школьные ПК).
5. **Отключаемость** — галка в настройках; политика приватности описывает только факт проверки версии (без телеметрии).

Реализация — веха v1.x (M12, «обновления»); настоящий документ фиксирует контракт и ограничения, чтобы не переписывать поставку.

## 9. Версионирование и воспроизводимость

- SemVer: `MAJOR.MINOR.PATCH` (пре-релизы: `-beta.N`); версия — в `Directory.Build.props`, тег git `v<версия>`; версия попадает в `VersionInfo` (Windows) и в `control` (deb).
- Воспроизводимость (best-effort): фиксированные версии NuGet + SHA-256 у lib3mf + фиксированная версия исходников Manifold; сборка детерминирована при одном SDK (.NET 10.0.x) и одном наборе нативных библиотек.
- CI (`.github/workflows/ci.yml`) собирает и тестирует обе ОС на каждый push; релизные артефакты собираются локально/в защищённом окружении, где доступен сертификат подписи (секреты не проходят через обычный CI).

## 11. Риски и известные ограничения

| Что | Статус / митигация |
|---|---|
| **Смоук `--smoke` не проходит проверку undo/redo** (на 2026-10-23: `historyWired=False`, `undoRedoWired=False` при `vcbCommitted=True`) | Состояние разработки приложения (связка «VCB → история → undo/redo», волна undo/redo), а не упаковки: publish/установка работают, GL-вьюпорт зелёный (500k треугольников, ≥ 58 FPS в смоуке). Блокирует п. 1 релизного чек-листа до закрытия задачи undo/redo |
| Иконка приложения (`smetana.ico` / `.png`) | **Заготовка:** перед релизом добавить `deploy/windows/assets/smetana.ico` и раскомментировать `SetupIconFile`; для Linux — `usr/share/icons/...` в `build-deb.sh` (в скрипте место под копирование иконки описано) |
| Отсутствие нативных библиотек в срезе | `publish.ps1` предупреждает и в `-RequireNatives` падает; чек-лист §10 п.3–4 |
| Ложные срабатывания антивирусов на свежих подписанных сборках | код-сигнинг + timestamp; заявка на белый список (Microsoft, Kaspersky) при первых срабатываниях |
| Timestamp-сервер и загрузка lib3mf требуют сети | только на машине сборки; приложение остаётся офлайновым (§7) |
| Санкции (R4) | хостинг сайта и файлов — в РФ; платежи — только РФ-агрегаторы ([payments.md](payments.md)); офлайн-активация без внешних сервисов |
| Лицензии зависимостей (R7) | SBOM на каждый релиз; новые зависимости — только после сверки с политикой (new-sbom.ps1, код выхода 2) |
| Монетизация/цены не утверждены (спека §7) | в [payments.md](payments.md) — тарифы-плейсхолдеры, решение — до старта продаж |
